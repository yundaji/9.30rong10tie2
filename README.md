# 每天定时按顺序循环发布10条

北京时间：08:00、09:30、11:00、12:30、14:00、15:30、17:00、18:30、20:00、21:30，每个时间发布一条。按 posts.json 的顺序发送，发完自动回到第一条，第二天继续昨天的位置。帖子池不足10条时会在当天循环使用。保留原项目的图文、视频和相册复制逻辑。

## GitHub更新步骤
1. 覆盖 main.py 和 .github/workflows/daily.yml（.github 是隐藏目录，也必须上传）。工作流文件需要放在默认分支。
2. 保留仓库自己的 posts.json 和 state.json，避免覆盖帖子池和发布进度；压缩包里是本次原上传版本。
3. 继续使用现有 BOT_TOKEN Secret、TARGET_CHAT 和 SOURCE_CHAT Variables。不需要 API_ID。
4. Actions中选择“每天定时按顺序循环发布十条”，Run workflow可检查。手动执行会补发当天已到时间的额度，因此晚上首次执行可能连续发多条；08:00前执行不会发帖。

只有发送成功才推进位置，进度自动提交回仓库。失败会在下一次运行继续尝试。同一天重复执行不会超过10条。22:45和23:45额外检查当天漏发额度；已发10条时不会再发。跨午夜不补发前一天的额度，帖子顺序仍保留。

GitHub定时任务可能延迟或漏运行，不能保证准点或每天发满10条。本地测试验证发送逻辑，没有连接Telegram实发。

## 调整时间
修改 main.py 的 POST_TIMES（保持十个时间、按升序、HH:MM格式），并同步修改 daily.yml 的cron。cron使用UTC，北京时间减8小时。不要删除state.json，否则发布位置会重置。
